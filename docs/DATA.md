# 数据说明（DATA）

本文档面向使用者与运维，说明 TBM Lite 把数据放在哪里、如何备份、如何恢复、如何排障。
设计细节与后续规划见 [`数据管理-安装-更新-方案.md`](./数据管理-安装-更新-方案.md)。

## 1. 数据目录

| 场景 | 目录 |
|---|---|
| 安装版（默认） | `%APPDATA%\TBM Lite`（即 Electron `userData`） |
| 便携模式 | exe 同级存在名为 `portable` 的空文件 → `exe 同级\data` |
| 自定义 | 环境变量 `TBM_DATA_DIR=<绝对路径>` |
| 开发态 | 仓库内 `electron/app-data/dev`（`TBM_DATA_DIR` 可覆盖） |

> 安装资源（程序本体）与用户数据完全分离：安装/升级只覆盖程序目录，**不会**触碰数据目录。

### 目录结构

```
<TBM_DATA_DIR or %APPDATA%\TBM Lite>\
├── .meta.json            安装标识、数据结构版本、最低可读版本、正常退出标记
├── db\
│   ├── app.db            SQLite 主库（WAL 模式）
│   └── app.db-wal/-shm   WAL 辅助文件（正常退出后可能仍存在，属正常现象）
├── files\                附件（按 sha256 内容寻址，只增不改）
│   ├── xqaa_t\<hash>.docx
│   └── .trash\<时间戳>\   删除/回收缓冲，7 天后自动清理
├── config\
│   ├── aj-api.json       AI 配置（API Key 经系统安全存储加密）
│   ├── chat-sessions\    AI 会话（保留 90 天 / 最多 200 条）
│   └── aj-api.example.json  安装种子模板（仅示例，无真实密钥）
├── logs\
│   ├── app.log           运行日志（单文件 5MB，保留 4 份轮转）
│   └── audit.log         删除 / 恢复 / 重置 / 导入 等审计记录
├── backups\
│   ├── auto\             滚动自动备份（含 pre-migrate / pre-restore / pre-import）
│   └── manual\           手动备份（不会被自动清理）
└── tmp\                  原子写暂存、换库暂存（每次启动清空）
```

## 2. 数据所有权与生命周期

| 数据 | 备份是否包含 | 升级时 | 卸载时 | 清理策略 |
|---|---|---|---|---|
| `db/app.db` | ✅ | 保留 | 询问后决定 | 永不自动删除 |
| `files/**` | ❌（见 §3 说明） | 保留 | 询问后决定 | 仅回收无引用文件，进 `.trash` |
| `config/aj-api.json` | ✅（密文） | 保留 | 询问后决定 | 仅「恢复出厂设置」删除 |
| `config/chat-sessions` | ❌ | 保留 | 询问后决定 | 90 天 / 200 条 |
| `logs/**` | ❌ | 保留 | 删除 | 5MB × 5 轮转 |
| `backups/**` | — | 保留 | 询问后决定 | 自动备份见 §3 |
| `tmp/**` | ❌ | 清空 | 删除 | 每次启动清空 |

## 3. 备份与保留策略

- 备份方式：SQLite `VACUUM INTO`，生成**一致性快照**（包含 WAL 中未落盘的事务）。
- 触发时机：
  - 每日首次启动后（`auto-daily-*`）
  - 退出时若当日尚无备份（`auto-exit-*`）
  - 迁移前（`pre-migrate-*`）、恢复前（`pre-restore-*`）、导入前（`pre-import-*`）、重置前（`pre-reset-*`）
  - 设置页「立即备份」（`manual-*`）
- 保留规则（`backups/auto`）：最新 5 份 + 每日 1 份（30 天内）+ `pre-*` 保留 7 天，总数上限 20；
  `backups/manual` 永不自动删除；最近 24 小时内的自动备份不允许手动删除。
- **备份只包含数据库**。附件是内容寻址、只增不改的物理文件，删除时会移入 `files/.trash`（7 天），
  因此误删附件通常可通过「打开数据目录 → files/.trash」找回。
- 每个备份旁边有同名 `.json` 侧车文件，记录备份类型、程序版本与数据结构版本。

## 4. 恢复流程（两阶段）

因为 libsql 原生驱动在 Windows 上不会随连接关闭释放文件句柄，恢复采用两阶段：

1. **阶段一（当前进程）**：校验备份 → 自动生成 `pre-restore` 副本 → 复制到 `tmp/pending-restore.db` → 写标记。
2. **阶段二（下次启动）**：在建立任何数据库连接之前换库，然后自动重启。

操作路径：`设置 → 数据与备份 → 备份列表 → 恢复`。恢复后应用会自动重启，界面数据即为备份内容。

异常处理：
- 待恢复文件校验失败 → 放弃恢复、保留当前数据，并把暂存文件改名留档，日志给出原因。
- 恢复后数据版本高于程序支持版本 → 启动门禁会拒绝写入并提示（见 §5）。

## 5. 版本门禁

`.meta.json` 记录 `schemaVersion` 与 `minReaderVersion`，程序启动时依次检查：

| 情况 | 行为 |
|---|---|
| 数据版本 = 程序支持版本 | 正常启动 |
| 数据版本 < 程序支持版本 | 自动迁移（迁移前强制备份） |
| 数据版本 > 程序支持版本 | **拒绝写入**：提示「退出 / 从备份恢复 / 打开数据目录」 |
| 程序版本 < `minReaderVersion` | 同上（防止降级程序写坏数据） |
| 上次未正常退出 | 执行 `PRAGMA quick_check`，通过则继续，失败则按损坏处理 |
| 数据库无法打开 | 判定损坏，引导从最近备份恢复 |

## 6. 一致性巡检与回收

`设置 → 数据与备份 → 完整性检查` 会检查：

- `PRAGMA integrity_check`（完整校验）
- 悬挂明细（所属需求书不存在）
- 悬挂需求书（所属项目不存在）
- 无主附件记录（归属需求书不存在）
- 附件记录但物理文件缺失
- 孤立物理文件（未被任何记录引用）

「清理孤立附件」会把孤立文件移入 `files/.trash/<时间戳>/`（可人工取回，7 天后自动删除）。

## 7. 重置

`设置 → 数据与备份 → 危险操作`：

| 操作 | 影响范围 | 确认词 |
|---|---|---|
| 清空业务数据 | 项目 / 需求书 / 明细 / 附件（含物理文件移入回收站），保留 AI 配置与偏好 | `CLEAR` |
| 恢复出厂设置 | 上述内容 + AI 配置 + AI 会话，保留备份与日志；下次启动重新进入首启向导 | `RESET` |

两者都会**先自动备份**（`pre-reset-*`），可从备份恢复。

## 8. 隐私与密钥

- 所有业务数据仅保存在本机数据目录，不做任何上报。
- 使用「需求书解析」与「AI 搜索」时，相关需求书内容会发送到你在设置页配置的第三方 AI 接口；
  不使用这两项功能则不外发。
- API Key 通过 Electron `safeStorage`（Windows DPAPI，绑定当前 Windows 用户）加密后存储；
  配置文件里只保存密文。换机器/换 Windows 账户后无法解密，程序会提示重新填写 Key，
  其余数据不受影响。
- 日志对 `token` / `apiKey` / `authorization` / `cookie` 等字段与 `sk-` 形式字符串自动脱敏。

## 9. 排障速查

| 现象 | 处理 |
|---|---|
| 提示「数据由更高版本创建」 | 安装对应或更高版本程序；或从备份恢复；或先「打开数据目录」备份后改名该目录重新开始 |
| 提示「数据库损坏」 | 在弹窗中选「从备份恢复」，程序会重启并换库 |
| 启动后数据为空 | 确认数据目录（设置页顶部显示实际路径）；检查是否误用 `TBM_DATA_DIR`；确认是否切换过 Windows 账户 |
| 附件打不开 | 完整性检查看是否「文件缺失」；可到 `files/.trash` 或备份中找回 |
| 磁盘占用增长 | 设置页查看各部分占用；清理孤立附件；`backups/auto` 会按保留策略自动收敛 |
| 想彻底清空 | 卸载时选「是」删除用户数据，或手动删除整个数据目录 |

## 10. 手工运维（可选）

```powershell
# 数据自检（无界面，输出 JSON 与退出码；建议对数据目录副本执行）
$env:TBM_DATA_DIR="D:\tbm-data"; npx electron . --tbm-smoke

# 校验数据一致性
npx tsx scripts/verify-migration.ts --dir D:\tbm-data

# 从旧 TBM 数据目录导入（脚本方式，产品内亦有向导）
npx tsx scripts/migrate-from-tbm.ts --from <旧数据目录> --to <新数据目录> [--dry-run]
```

> ⚠️ 不要用文件复制的方式备份 `app.db`：WAL 模式下可能丢失尚未 checkpoint 的事务。
> 需要手工备份时请使用程序内的备份功能，或用 sqlite 的 `VACUUM INTO`。
